StudyFlow 用户端前端 —— AI 对话记录导出
工具：Claude Code
日期：2026-09-02（D2）
阶段：页面开发 + 本地 mock + 构建验证

========== 1 ==========
【提问】
实现登录/注册页：邮箱+密码登录，注册需昵称/邮箱/密码/确认密码，表单校验（邮箱格式、密码≥6 位、两次一致、必填）。

【收获】
掌握了 Element Plus 表单校验规则（rules + validator）和登录后跳回原目标页（redirect query）的写法。

========== 2 ==========
【提问】
实现主布局：左侧侧边菜单 + 顶部用户下拉（退出带确认），菜单高亮跟随当前路由。

【收获】
用 el-menu 的 router 模式 + default-active 跟随路由，实现了菜单与路由联动。

========== 3 ==========
【提问】
实现首页（问候 + 三张统计卡 + 快捷操作 + 最近计划）和计划列表/编辑（状态筛选、分页、删除确认、日期范围校验）。

【收获】
复用同一表单做新建/编辑（用路由参数判断），避免两套代码；日期校验用自定义 validator。

========== 4 ==========
【提问】
实现每日打卡页：选计划+日期，填时长/完成/笔记/图片，保存 PUT 打卡；同一天重复提交为更新不新增；右侧列打卡记录。

【收获】
理解了「打卡 upsert」语义（UNIQUE(user_id, plan_id, check_date)），前后端口径一致。

========== 5 ==========
【提问】
实现统计+日历页：选计划展示累计时长/完成率/连续天数，月历标记已完成日期。

【收获】
前端只展示后端算好的统计口径，不自己算（团队文档 5.4 要求后端统一计算）；月历用 computed 生成格子。

========== 6 ==========
【提问】
后端未就绪，请按统一接口契约用 Vite 插件实现本地 mock，覆盖全部接口并体现 401/403/404/409 语义。

【收获】
把「契约」变成了可运行的假后端，前端可以独立开发；后端就绪后改环境变量切换，代码不动。

========== 7 ==========
【提问】
运行 npm run build 做类型检查和生产构建，修复报错。

【收获】
踩到 TS 6.0 弃用 baseUrl 的坑：删掉 baseUrl 只留 paths 即可。养成「写完就跑类型检查」的习惯。
