========== 1 ==========
【提问】
阅读《StudyFlow 五人分工统一执行方案》和《小白执行版》两份文档，帮我梳理我（负责用户端前端）要交付哪些页面和核心层文件、各接口的路径与字段、验收标准和测试点。

【收获】
明确了 5 个页面（登录/注册、首页、计划、打卡、统计）+ 4 个核心层文件（client/store/router/constants），以及统一响应结构 {code,message,data,requestId}、字段 camelCase 等硬性约定。先看清「要做什么」再动手。

========== 2 ==========
【提问】
用 Vue3 + Vite + TypeScript 初始化前端项目，装 Element Plus / Pinia / Vue Router / Axios，配 @ 别名和中文 locale。

【收获】
搭好骨架。过程中确认团队用 TypeScript（文档里是 .ts 文件），统一了约定，避免和队友格式冲突。

========== 3 ==========
【提问】
封装全项目唯一的 Axios 实例：请求拦截器自动带 JWT、响应拦截器解包统一响应、401 统一登出，并给出类型化的 get/post/put/patch/delete 封装。

【收获】
理解了拦截器机制：请求拦截器统一塞 token，响应拦截器统一解包和报错，业务代码不再重复处理鉴权和错误提示。

========== 4 ==========
【提问】
按文档字段字典用 TS 定义契约类型：User / StudyPlan / CheckIn / Statistics / Page<T> / ApiEnvelope<T>。

【收获】
把后端契约用类型固定下来，字段名严格 camelCase，后续联调时类型就是「活的接口文档」。

========== 5 ==========
【提问】
用 Pinia 实现唯一认证状态源，配全局路由守卫：未登录跳登录、已登录访问登录页跳首页、有 token 无 user 先拉 me。

【收获】
理清「一个认证状态源 + 一套守卫」的写法，token 持久化到 localStorage，刷新不丢登录态。

========== 6 ==========
【提问】
把计划状态、用户状态/角色等枚举的中文文案和 tag 颜色集中到一个常量文件。

【收获】
统一文案来源，避免每个组件各写一套状态映射（团队文档 5.3 的硬性要求）。
