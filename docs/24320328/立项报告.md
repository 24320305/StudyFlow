# StudyFlow 立项报告

> 成员：汪晨烨（24320328，用户端前端）· 陈亦雷 · 鲍奕涵 · 成泽楷 · 陈瀚锐

## 一、项目背景与问题
大学生普遍存在「计划制定容易、坚持执行困难」的问题：学习计划常因缺乏监督而半途而废，学习过程没有沉淀，个人学习缺少同伴激励。市面上笔记类工具偏重记录，缺乏计划—执行—反馈的闭环。本项目希望把「制定计划、每日打卡、数据反馈、社区监督」串起来，降低坚持学习的门槛。

## 二、目标用户与需求
目标用户为在校学生。核心需求：
1. 便捷制定与调整学习计划；
2. 低成本的每日打卡（记录时长、完成情况、笔记、图片）；
3. 直观的学习统计反馈（累计时长、完成率、连续天数）；
4. 同伴间的动态分享与互相监督；
5. 管理员对用户与内容的审核管理。

## 三、功能设计
- **用户模块**：注册 / 登录（JWT）/ 个人资料，角色 USER、ADMIN。
- **计划模块**：创建、查询、更新、删除；状态 ACTIVE / PAUSED / COMPLETED。
- **打卡模块**：按计划 + 日期记录打卡，同一天重复提交为更新；字段含时长、完成、笔记、图片。
- **统计模块**：累计时长、完成率、连续打卡天数，由后端统一计算。
- **社区模块**：打卡动态、评论、举报与审核。
- **后台模块**：用户管理、内容审核。

## 四、技术方案
- 前端：Vue 3 + Vite + TypeScript + Element Plus + Pinia + Vue Router + Axios；本地 mock 先行。
- 后端：Spring Boot + MyBatis + MySQL；JWT 认证；统一响应 `{ code, message, data, requestId }`。
- 约定：Java / JSON / Vue 用 camelCase，数据库 snake_case；打卡与动态分离；通知功能 P2 预留。

## 五、接口设计（概要）
| 模块 | 接口 |
| --- | --- |
| 认证 | POST /api/auth/register、/login、/logout；GET/PATCH /api/me |
| 计划 | POST/GET /api/plans；GET/PATCH/DELETE /api/plans/{id} |
| 打卡 | GET /api/plans/{id}/check-ins；PUT /api/plans/{id}/check-ins/{date} |
| 统计 | GET /api/statistics |
| 上传 | POST /api/uploads；DELETE /api/uploads/{fileId} |

统一错误语义：401 未登录 / 403 无权限或账号受限 / 404 不存在或不可见 / 409 重复或非法状态流转。
