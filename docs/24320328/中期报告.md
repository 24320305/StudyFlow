## 一、工作成果

我负责 StudyFlow 的用户端前端，已交付一套可独立运行、严格遵循团队接口契约的前端工程。

### 1. 页面（`src/views/`）
- 登录 / 注册页：邮箱格式、密码长度、两次密码一致等表单校验，登录后跳回原目标页。
- 首页：昵称问候、进行中/已完成/全部计划三张统计卡、快捷操作入口、最近计划列表。
- 学习计划列表与编辑：状态筛选、分页、删除二次确认，结束日期不得早于开始日期、每日目标大于 0。
- 每日打卡：选择计划与日期，记录时长/完成/笔记/图片，同一天重复提交为更新而非新增。
- 学习统计与日历：累计时长、完成率、连续打卡天数三张指标卡 + 月历标记已完成日期。
- 主布局：侧边菜单 + 顶部用户下拉，菜单高亮跟随当前路由。

### 2. 核心层
- 全项目唯一 Axios 实例（`api/client.ts`）：请求拦截器自动带 JWT，响应拦截器解包统一响应 `{code,message,data,requestId}`，401 统一登出。
- 唯一认证状态源（`stores/auth.ts`）+ 全局路由守卫（`router/index.ts`）。
- 契约类型（`api/types.ts`）与状态枚举中文文案集中（`core/constants.ts`）。

### 3. 本地 mock 与测试
- 后端未就绪时，用 Vite 插件实现本地 mock（`mock/index.ts`），接口路径、字段、401/403/404/409 语义严格按契约，改环境变量 `VITE_USE_MOCK=false` 即可切换真实后端。
- 用 curl 逐项验证：重复邮箱注册 409、越权访问他人计划 404、同一天打卡幂等、统计口径正确（完成率、连续天数）。

### 4. 代码提交
- 本地分支 `feat/wang-frontend` 已推送到团队仓库，未直接改动 main；提交记录含前端初始化、仓库结构补齐、日报与提示词等。

## 二、过程小结

### 1. 需求理解
先通读两份分工文档，明确自己的职责边界（5 个页面 + 4 个核心层文件）和统一约定（camelCase、统一响应结构、状态枚举集中），再动手，避免了和队友的字段/命名冲突。

### 2. 关键问题与解决
- **TypeScript 6.0 弃用 baseUrl**：构建报 `TS5101`，确认 `paths` 可脱离 `baseUrl` 单独使用后删除解决。
- **mock 打卡接口返回「方法不支持」**：排查发现 `/plans/{id}/check-ins/{date}` 被「计划详情」分支抢先匹配，给详情分支加「无第三段才走详情」的判定后修复。
- **GitHub 推送卡在认证**：本机无 gh、无 SSH key、无凭据，Git Credential Manager 弹窗超时；重新发起推送用浏览器登录授权后解决。
- **打卡图片无法回显**：mock 不解析 multipart，改为字段存后端返回的 url、本地用 objectURL 预览，展示与契约两不误。

### 3. AI 辅助的使用与反思
AI 帮我大幅加速了脚手架搭建和页面代码生成，但核心架构（拦截器、路由守卫、mock 切换）是我主动梳理并确认理解的；接口契约验证我选择自己用 curl 逐项跑通，而不是只依赖 AI 说「应该没问题」。过程中也发现并修复了 AI 生成代码里的一个真实路由 bug。

### 4. 团队协作
个人产出按「学号子目录」隔离，日报、提示词记录按课程要求每日提交；接口字段严格遵循统一契约，联调前把「注册是否返回 token、统计是否需 planId」等假设在 README 中标注，待与后端核对。
